General

This service's own HTTP server and how much it logs. Rarely needs changing after initial setup.

Behind the nginx setups install.sh configures, keep this 127.0.0.1:<port> — nginx is the only thing that should reach this process directly. Only use 0.0.0.0:<port> if you're intentionally exposing this service to the network without a reverse proxy in front of it. Takes effect on restart.

Logging

Verbosity and encoding of what this process writes to stdout/journal.

debug is very verbose (every panel request, cache hit/miss) — use it temporarily while diagnosing an issue, not permanently. info is the recommended default.
json — one JSON object per line, best for journald/a log aggregator. console — human-readable colored text, nicer for tailing directly in a terminal.

API (3x-ui panel connection)

Required

How this service reaches the 3x-ui panel it manages subscribers on. Nothing else works until both fields below are set.

E.g. http://127.0.0.1:2053 if this service runs on the same box as the panel, or https://panel.example.com:2053 otherwise. Must match the panel's actual listen address/port (and base path, if it has one).
Generate this in the panel's own UI: Settings → Security → API Token. Anyone with this key can fully manage the panel's inbounds and clients — treat it like a password.
Max time to wait for one panel request before treating it as failed. Default 10s.
How many times to retry a request that times out or gets a 5xx from the panel. Doesn't apply to a 401/403 (bad API key) — that fails immediately. Default 3.
Base delay between retries — the Nth retry waits backoff × N. Default 0.5s.
Only enable this for a panel behind a self-signed certificate you've personally vetted and that isn't reachable from the public internet. Leaving this off protects your API key from a man-in-the-middle on the connection to the panel.

Subscription

Required

What subscribers' links are built from, and how the panel's client list is cached.

The base URL subscribers' links (/sub/<id>, QR codes, generated client configs) are built from — must be a URL a client can actually reach from outside. If this service sits behind a reverse-proxy random path (as install.sh's dedicated/panel modes set up), include that path here too, e.g. https://your-domain/AbC123xyz. Getting this wrong is the single most common cause of "the subscription link doesn't work" reports.
Usually this server's public IP or domain. Only used when an inbound's own listen address is a wildcard (0.0.0.0 or ::) and therefore not itself usable as a client connect address.
Reserved for a future client-refresh hint; not read by anything in this version yet. Safe to leave at default.
How long the panel's inbound/client list is cached in memory before re-fetching. Lower = panel-side changes show up here sooner but more load on the panel API; higher = the opposite. Default 30s.
Advanced: edit raw JSON

QR Codes

Appearance of the QR code generated for each subscriber's link.

Image size in pixels (square). Default 256; larger helps scanning from a printed page.
Quiet-zone border around the code, in QR "modules" (not pixels). Default 4 — too small and some scanners fail to read it.
Color of the QR code's dark modules.
Color behind the QR code. Keep strong contrast against the foreground or scanners may fail.

Security

Rate limiting, the response Content-Security-Policy, and reserved host validation.

Steady-state requests allowed per client IP per minute before responses start getting rate-limited (429). Default 60.
Extra requests allowed in a short burst above the steady rate. Default 20.
Note: rate limiting currently keys on the request's raw remote address. Behind install.sh's nginx reverse-proxy setups, that address is always nginx's own loopback IP — in practice all visitors currently share one bucket rather than being limited individually.
Sent on every admin response. The default already allows the small inline script/style the admin UI's own theme toggle needs — an incorrect value here can lock you out of parts of this very admin UI. Only edit if you know what these directives do.
Reserved for future Host-header validation; not currently enforced by any request handler in this version. Safe to leave empty.
